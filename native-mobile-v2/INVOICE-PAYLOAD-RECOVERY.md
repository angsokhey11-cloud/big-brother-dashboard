# Online exact-product cash/credit payload and recovery foundation
Draft preview prepares p_invoice and p_payment using existing field names, base-unit stock allocations and selling-unit metadata, stable draft/line identities, and customer due-date terms (DAYS, MONTHS, HALF_MONTH) plus optional explicit override. Cash, Credit and Partially Paid in Cash only; no bank or group-product submission. Rounding, ID format, customer/salesperson identity and server schema must be validated with isolated fixtures before enabling any write. No save RPC is invoked.
Account-scoped private SharedPreferences journal stores ID, invoice number, timestamp and SHA-256 of exact frozen arguments, not full customer/bank payload. Synchronous commit before future send, blocks any new attempt while record exists. Read-only recovery check uses existing verification endpoint; not-found remains unresolved; no automatic retries or clearing. Journal begin/acknowledge methods are intentionally not wired to a submit action yet. Before release, exercise process death, network failure and account switching in instrumentation tests, check backup exclusion and ensure backend accepts ID format. No production or Local changes.

# Bank payload and atomic save coordinator
All six methods can prepare a development payload. Single-bank and split payment preserve existing invoice/payment contract fields. Actual source currency/amount remain in the separate captured selection used by preflight; do not invent unverified SQL fields. Multiple registered sources are preview-only, admin, same currency, Bank/Partial Bank, 2–30 sources with stable request ID. Endpoint selection is a preview, not deployment authorization. Cross-currency single-bank posting contract, manual admin transaction ID, exact rounding, stock/group allocation and server behavior still require isolated integration tests. No real transport or Complete button is enabled.
Transport-independent coordinator records frozen endpoint and args before send, verifies once even after success or error, retains unresolved journal on not-found/failed verification, and never retries automatically. CI fake-transport tests cover 7 recovery scenarios. Actual SharedPreferences journal and authenticated RPC transport are not yet wired into this coordinator; use isolated backend fixtures before production activation. No production or Local changes.
